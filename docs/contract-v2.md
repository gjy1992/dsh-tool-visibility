## AC1（修订后）

未配置任何分组时与 0.4.0 一致：

- 基线来源 = **当前工作副本**；生成夹具时断言 `package.json` 的 `version === "0.4.0"`，
  并记录 `src/index.js`、`src/client.js` 的 sha256（该目录非 git 仓库，无 commit sha）。
- 比对粒度 = **工具名有序集合** + 设置页**逐工具开关、全部恢复、前缀分组、set-group** 的存在性与可用性。
- 工具 `description` 的具体文案**不参与**比对。

## AC6（修订后）

披露状态按 **agent 会话 id** 判定：

- 同一 agent 会话内，披露在后续轮次保持有效。
- 新建 agent 会话（新会话 id）即视为新会话，回到「仅含披露工具」的初始态；进程重启同样回到初始态。
- 披露集合只存内存，**不写入** `tool-visibility.json`。

## AC8（修订后）

- 分组机制不收纳未归组工具：它们不进入任何组的 deny 集合、不参与披露，始终处于「未归组」状态。
- **hidden 对所有工具（归组与未归组）一致优先**：未归组工具被 hidden 时不可见，取消 hidden 后可见。
- `run_code` 与 `tool_visibility` 既不能写入分组成员，也不能被 hidden。

## 分组存储格式（AC2 artifact）

`tool-visibility.json` 的 `groups` 为数组，每项：

- `key`：小写标识符 `/^[a-z][a-z0-9_]{0,31}$/`，创建后不可变，披露工具名为 `group_<key>`。
- `label`：显示名（改名只改它，不改 key）。
- `intro`：**组介绍**，同时是 `group_<key>` 工具的 description（严格全等）。
- `members`：工具名数组；禁止 `run_code`、`tool_visibility`、任何 `group_*` 与跨组引用；未知名在加载时忽略。
- `enabled`：布尔；`false` 时不注册披露工具、成员退回未披露集合并按 hidden 规则显隐。

未识别的顶层键与未识别的组内字段在重写时保留。

## 分组语义（AC3 / AC8）

- 初始态：模型侧视图 = 全部启用组各一个 `group_<key>` ∪ 全部未归组工具（扣 hidden）；组成员不在视图中。
- 披露：调用 `group_<key>` 后，该组未被 hidden 的成员在**同一 agent 会话的下一步**进入视图。
- `hidden` 对所有工具（归组与未归组）优先；未归组工具不进入任何组的 deny 集合。
- 披露状态只存内存，按 agent 会话隔离，不写入 state 文件。
